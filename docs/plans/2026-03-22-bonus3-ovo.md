# Bônus 3: 365 Maneiras de Comer Ovo Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Create a new standalone React application and integrate data for the "Bônus 3: 365 Maneiras de Comer Ovo" feature, using the established editorial wellness aesthetic and a horizontal 16:9 image aspect ratio.

**Architecture:** We will create a new standalone Vite entry point (`ReceitasOvoApp.tsx` and `receitas-ovo/index.html`). The 365 recipes will be parsed from the provided text files and split into data chunks of 10 recipes per file (`receitasOvoVol01.ts`, `receitasOvoVol02.ts`, etc.) to optimize bundle size and performance. We will reuse the existing `BonusRecipeBookApp` component for the UI, ensuring consistency with previous bonuses. Image placeholders will use the `BonusPlaceholderVisual` type with explicit 1376x768 dimensions and a 16:9 aspect ratio.

**Tech Stack:** React, TypeScript, Vite, Tailwind CSS v4.

### Task 3: Develop Scripts for Semi-Automated Data Extraction

Since there are 365 recipes, manually copying and pasting will be error-prone and time-consuming. We need to create a Node script to parse the semi-structured `.txt` files into `.ts` volumes.

**Files:**
- Create: `scripts/parseOvoRecipes.mjs`

**Step 1: Write the parsing script**

Create a script `scripts/parseOvoRecipes.mjs` that reads the `.txt` files, uses regex heuristics to identify Title, Ingredients, Steps, and then formats them into the TypeScript structures defined in Task 2. This script should handle chunking the output into arrays of 10 recipes and writing them to `receitasOvoVolXX.ts` files.

*Note: Since the text formats vary (Volume 1-7 in one file, Vol 8 e 9 em outros, com índices e formatações distintas), the script will need robust fallback logic or we will apply an LLM-powered extraction approach iterating over chunks of text.*

**Strategy for execution:** The agent executing this plan will need to either write a very smart regex parser OR use a tool to process chunks of text through the LLM to output structured JSON/TS, saving it volume by volume.

**For manual verification of the parser:**
Run: `node scripts/parseOvoRecipes.mjs`
Expected: Output `.ts` files in the src/content/bonus directory containing structurally valid recipes.

### Task 4: UI Updates for High Volume Navigation (Volumes)

The current `BonusRecipeBookApp` displays all recipes in a single grid. With 365 recipes, this will be overwhelming and slow. We need to implement a Volume selector or pagination mechanism.

**Files:**
- Modify: `client/src/components/bonus/BonusRecipeBookApp.tsx`

**Step 1: Implement Volume/Pagination Logic**

1.  Add state: `const [currentVolume, setCurrentVolume] = useState(1);`
2.  const `RECIPES_PER_VOLUME = 10;`
3.  Calculate total volumes: `Math.ceil(filteredRecipes.length / RECIPES_PER_VOLUME)`
4.  Slice `filteredRecipes` to display only the current volume: `const visibleRecipes = filteredRecipes.slice((currentVolume - 1) * RECIPES_PER_VOLUME, currentVolume * RECIPES_PER_VOLUME);`
5.  Add a UI component (Volume Navigator) above the recipe grid.

**Step 2: Write Navigation UI**

```tsx
// Inside BonusRecipeBookApp, before the grid:
{totalPages > 1 && !searchQuery && (
  <div className="mb-6 flex flex-wrap gap-2 justify-center items-center">
    {Array.from({ length: totalPages }).map((_, i) => (
      <button
        key={i}
        onClick={() => setCurrentVolume(i + 1)}
        className={cn(
          "px-3 py-1.5 rounded-full text-sm font-medium transition-colors border",
          currentVolume === i + 1
            ? "bg-[var(--color-rose)] text-white border-[var(--color-rose)]"
            : "bg-white text-[var(--color-charcoal)] border-[var(--color-taupe-light)] hover:bg-[var(--color-ivory)]"
        )}
      >
        Vol. {String(i + 1).padStart(2, '0')}
      </button>
    ))}
  </div>
)}
```
